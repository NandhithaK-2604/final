Improve the Payroll Batch Details page to make it look clean, compact, modern, and professional.

The current implementation feels too large because the entire page is placed inside one oversized card with excessive empty space. Reduce the overall footprint of the page and improve the visual hierarchy.

VERY IMPORTANT — DO NOT CHANGE ANYTHING ELSE

- Modify ONLY the Payroll Batch Details page/component and its page-specific styling.
- Do NOT modify any other page.
- Do NOT modify any shared component.
- Do NOT modify "variables.css".
- Do NOT modify global CSS/global styles.
- Do NOT change global variables.
- Reuse the existing shared components and existing design system.
- Use the existing variables from "variables.css" wherever styling values are required.
- Do not introduce new hardcoded global colors, spacing variables, typography variables, etc.
- Do not create duplicate components when an existing shared component can be reused.
- Do not change routing, API calls, state management, validation, handlers, business logic, or existing functionality.

Main design direction

Do NOT make the whole page one large card.

The current page has too much empty space and the outer container occupies almost the entire screen.

Instead:

- Use the normal page background.
- Remove/reduce the oversized outer card.
- Use small, purposeful containers/cards only where necessary.
- Reduce vertical padding and margins.
- Keep the content visually compact.
- Make the payee table the main focus of the page.

The page should look like a professional enterprise transaction/detail page, not a dashboard.

Page structure

Use this hierarchy:

Back navigation

"← Back to Payroll Batches"

Then a compact batch header:

"BATCH-1787801993513-553"                              "Draft"

Below it, display the metadata in one compact horizontal row:

"Debit Account: 1000293847   |   Currency: INR   |   Payment Date: 27 Aug 2026"

Do not create a large empty card around this information.

Payee section

Keep:

Payee Details (1)

Place these actions on the same row:

"+ Add Payee"   "Reset Rows"

Keep the spacing compact.

Payee table

The table should be the primary content area.

Keep the existing columns:

- Employee ID
- Name
- Account Number
- IFSC/SWIFT
- Amount
- Actions

Improve:

- column alignment
- typography
- row height
- padding
- borders
- header styling
- spacing
- readability

Do not make the table unnecessarily tall.

Keep the existing editable fields and functionality exactly as they are.

Keep the existing Remove action.

Pagination

Keep the existing pagination logic and controls.

Place:

"Showing 1–1 of 1"

on the left and pagination controls on the right.

Do not give pagination a large separate card.

Totals

Keep:

"Total Payees: 1"

and

"Total Amount: ₹0.00"

Do not create large statistic cards.

Bottom actions

Keep the existing buttons:

- Back to list
- Save as Draft
- Submit for Approval

Align them neatly toward the bottom-right.

Use the existing shared Button component.

Maintain the existing visual hierarchy:

- Back to list → secondary
- Save as Draft → secondary
- Submit for Approval → primary

Do not change their handlers or functionality.

- excessive top padding
- excessive card padding
- large gaps between sections
- unnecessary whitespace around the table

1. Batch ID/status
2. Batch metadata
3. Payee Details

without the page feeling oversized.
