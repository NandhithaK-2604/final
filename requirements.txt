Modify the batch management frontend according to the following requirements.

1. REMOVE THE DUPLICATE BUTTON FROM THE BATCH LIST PAGE
- In the Create Batches / Batch List table, remove the "Duplicate" button from the Actions column.
- The Actions column should only show "View" (and existing actions such as Edit/Delete where applicable).
- Do not remove or modify the existing View functionality.

2. ADD DUPLICATE BATCH TO THE VIEW BATCH PAGE
- When the user clicks "View" for a batch, open the existing Batch Details/View page.
- Add a "Duplicate Batch" button in the TOP-RIGHT corner of the Batch Details page.
- Place it near the page heading/status and make it visually prominent but consistent with the existing UI.
- Use an appropriate duplicate/copy icon.
- Button label should be "Duplicate Batch".

3. REJECTION REASON
- If the batch status is "Rejected", display the rejection reason clearly near the top of the View Batch page, below the batch header/basic information.
- Use a clearly distinguishable alert/card section.
- Heading: "Rejection Reason"
- Display the actual rejection reason returned by the backend.
- Use the existing red/error styling for the rejected status.
- Do NOT hardcode the rejection reason.
- If the batch is not rejected, do not display the rejection reason section.

...

4. DUPLICATE FUNCTIONALITY
- When "Duplicate Batch" is clicked, call the duplicate batch API that already exists in the backend.
- Pass the original batch ID to the API.
- The backend should generate the new unique Batch ID.
- After successful duplication, navigate the user to the appropriate Create/Edit Batch page for the newly duplicated batch.
- The duplicated batch must be treated as a new batch.
- Do not copy the old approval/rejection status into the new batch.
- Do not modify the original batch.

5. IMPORTANT
- Reuse the existing API service, components, styling, routing and state-management patterns wherever possible.
- Do not create duplicate components unnecessarily.
- Do not break the existing View, Create, Edit, approval, rejection, or pagination functionality.
- Handle API loading, success and error states properly.
- Show a success/error message after the duplicate operation.
- Make the UI responsive and consistent with the existing application design.

Before making changes, inspect the existing batch list component, View Batch component/page, routing, API service, and batch DTO/model to understand the current implementation. Then modify only the required files.
