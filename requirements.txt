Modify the EXISTING Batch View/Details page to match the attached/reference UI design as closely as possible.

IMPORTANT:
- Do NOT create a new page from scratch.
- Do NOT change the existing backend API contracts.
- Reuse the existing components, data, routing, API calls, and styling framework.
- Only modify the layout, positioning, styling, and required UI logic.

TARGET DESIGN:

1. PAGE HEADER
- Keep the existing SavnyaPay/Standard Chartered header and left sidebar.
- At the top of the content area show:
    "Back to list"
    "Batch Details"
    Batch ID below the heading.
- On the TOP-RIGHT of the page header, add:
    [ Duplicate Batch ]
- Use a copy/duplicate icon.
- The button should be BLUE/PRIMARY, NOT green.
- Do not place the Duplicate button below the batch information.
- Do not place Duplicate in the payee table.
- Do not show Duplicate in the batch list/table Actions column.

2. BATCH SUMMARY CARD
Immediately below the page header, display the batch summary in a clean horizontal card.

Show:
- Debit Account
- Transaction Currency
- Payment Date
- Created By
- Status

Example:

Debit Account       Transaction Currency    Payment Date      Created By
SC-USD-001          USD                     04-09-2026        Yash Operator

                                                      [ Rejected ]

Use a red/pink badge for Rejected.

3. REJECTION REASON
If the batch status is REJECTED, display a full-width rejection alert directly below the summary card.

Design it like:

┌─────────────────────────────────────────────────────────────┐
│  !    Rejection Reason                                      │
│       Payment details are incomplete. Please review the    │
│       payee information and resubmit.                      │
└─────────────────────────────────────────────────────────────┘

Requirements:
- Light red/pink background.
- Red border.
- Red warning/error icon on the left.
- "Rejection Reason" should be bold.
- Actual rejection reason must come dynamically from the backend response.
- NEVER hardcode the rejection reason.
- If there is no rejection reason or status is not REJECTED, hide this alert completely.

4. PAYEE DETAILS
Below the rejection reason, show the existing Payee Details table.

Keep the existing payee data and API functionality.

Use a clean white card with:
"Payee Details (2)"

Table columns:
- #
- Employee ID
- Name
- Account Number
- IFSC/SWIFT
- Amount

Keep the existing pagination and total amount functionality.

5. SPACING AND DESIGN
Make the page visually similar to the reference design:
- White/light background.
- Rounded cards.
- Subtle borders/shadows.
- Consistent spacing.
- Blue primary buttons.
- Red only for rejected status/rejection alert.
- Do not use green for the Duplicate Batch button.
- Align all content properly.
- Make the page responsive.

6. DUPLICATE BEHAVIOUR
When the user clicks "Duplicate Batch":
- Call the existing duplicate batch API.
- Pass the current/original Batch ID.
- Backend must generate a new unique Batch ID.
- Do NOT modify the original batch.
- Do NOT copy the REJECTED status to the new batch.
- The duplicated batch should be treated as a new batch/draft.
- After successful duplication, navigate to the appropriate Create/Edit Batch page for the newly created batch.
- Show a success message if duplication succeeds.
- Show a meaningful error message if the API fails.
- Disable the button while the API request is in progress to prevent duplicate requests.

7. BATCH LIST PAGE
Remove the Duplicate button from the Batch List table completely.

The Actions column should NOT contain Duplicate.

The user flow should be:

Batch List
    ↓
View
    ↓
Batch Details
    ↓
See Rejection Reason
    ↓
[ Duplicate Batch ]
    ↓
New duplicated batch

8. DO NOT BREAK EXISTING FUNCTIONALITY
Before modifying the code, inspect:
- Existing Batch List component
- Existing Batch View/Details component
- Existing routing
- Existing batch API service
- Existing batch model/interface/DTO
- Existing rejection-status handling

Reuse the existing implementation wherever possible.

The final View Batch page should visually follow the reference image:
- "Batch Details" on the left
- "Duplicate Batch" on the top-right
- Batch summary card underneath
- Rejection Reason alert underneath the summary for rejected batches
- Payee Details table underneath
- Existing pagination and Total Amount at the bottom

Do not introduce unnecessary new APIs, components, or dependencies.
